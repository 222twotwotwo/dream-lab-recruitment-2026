# 示例课题：油你点评（校园点评社区）

> 本文档是 OA 系统的**第一份示例课题设计**，展示如何用《需求文档.md》中的课题 / 模块 / 任务 / 申请书字段组织一个真实课题。管理用户可直接按本文档在 OA 后台录入课题、模块与评审标准；学生按第 6 章要求准备申请书。

**名称释义**：「油你点评」谐音「由你点评」——每一条点评都由你写就；「油」呼应校园食堂与市井烟火气。Slogan：**油你点评，生活有谱**。

## 2. 产品定位

### 2.

| 大众点评 | 油你点评（校园版） |
| --- | --- |
| 商户（餐厅、商场） | 商户：食堂窗口、奶茶店、打印店、健身房 |
| 地点（景点、商圈） | 地点：自习室、实验室、操场、会议室、快递点 |
| 达人 / 榜单人物 | 人物：社团负责人、讲座嘉宾、网络人物 |
| 活动 / 演出 | 事件：讲座、比赛、招新活动、晚会 |
| 发表点评 + 星级打分 | 发表点评 + 1~5 星综合分 + 分维度打分 |
| 上传图片 | 每篇点评最多 9 张图，压缩后上传 |
| 评价 / 讨论 | 点评下两级评论、点赞、@提及、举报 |
| 搜索 / 榜单 / 筛选 | 关键词搜索、按评分 / 最新排序、分类标签筛选 |

### 2.2 核心功能清单（课题产出范围）

1. **点评对象中心**：四类对象（商户/地点/人物/事件）的创建、编辑、分类、封面、状态管理；用户可"申请新增"对象，管理用户审核。
2. **点评与打分**：发布点评（标题+正文+打分+图片+标签）；1~5 星综合分；按对象类型展示分维度分数；综合分聚合展示。
3. **图片上传**：多图上传、自动压缩、对象存储、鉴权读取、首图设为封面。
4. **评论与讨论**：点评下评论与回复（两级）、点赞、@用户、举报。
5. **内容审核**：点评先审后发；评论先发后审 + 举报处理；敏感词过滤；下架/恢复。
6. **搜索与发现**：关键词、标签、分类筛选；评分 / 最新 / 最多点评排序；分页。
7. **用户体系**：注册登录、个人主页（我的点评/评论/收藏）、点评数与获赞数徽章。
8. **响应式前端**：PC / 移动端可用，星级交互、点评编辑器、图片墙与懒加载。

## 3. 业务规则（产品侧，写入课题描述）

### 3.1 打分规则

| 对象类型 | 分维度 |
| --- | --- |
| 商户 | 性价比、环境、服务 |
| 地点 | 便利度、舒适度、设施 |
| 人物 | 专业度、亲和度、靠谱度 |
| 事件 | 组织水平、内容质量、性价比 |

- 每个维度 1~5 星，**综合分 = 各维度平均分**（保留 1 位小数），列表页展示综合分与点评总数。
- 同一用户对同一对象**只能发布一条点评**；可修改，修改后重新进入审核。

### 3.2 图片规则

- 每篇点评 0~9 张，单张 ≤ 5MB，支持 JPG/PNG/WebP。
- 上传后压缩至长边 ≤ 1080px，存对象存储私有桶，经鉴权接口读取（对齐 OA 简历/二维码的私有存储原则）。
- 首图作为列表卡片封面；用户可删除自己上传的图片。

### 3.3 评论与讨论规则

- 评论两级（对点评的评论 + 回复）；支持点赞、@用户、举报。
- 评论先发后审：命中敏感词自动隐藏，人工复核后恢复或删除。
- 被举报内容进入审核队列，处理结果通知当事人。

### 3.4 审核规则

- **点评**：先审后发——提交后进入待审核队列，管理用户通过后公开。
- **对象（商户/地点/人物/事件）**：用户可申请新增，管理用户审核通过后开放点评。
- 审核拒绝须填写原因，提交人可修改后重新提交。

### 3.5 人物点评合规规则（评审时重点提问）

- 人物类对象默认**限制为校内公开身份**（导师、助教、活动嘉宾等），不开放对普通学生的点评。
- 人物点评仅展示三个正向维度（专业度/亲和度/靠谱度），无综合负向维度。
- 被点评人可提出异议，经审核后隐藏或删除不当点评；人物对象可申请关闭点评。

## 6. 报名与申请书要求

### 6.1 报名设置

- 报名窗口：2026-03-09 ~ 2026-03-29；开启审核，报名须同步提交申请书（D16）。
- 人数上限 12，报满即止；审核拒绝释放的名额可在截止前被继续报名（D12）。

### 6.2 申请书要求（对应 application 字段）

| 申请书字段 | 要求 |
| --- | --- |
| 个人陈述 | 500~3000 字：为什么想做点评类产品、对 UGC 社区的理解、个人特点 |
| 对课题的理解 | 从 8 个模块中**选择 1 个意向模块**，说明该模块的职责、技术方案与边界（可画图） |
| 实施计划 | 按第 7 章里程碑写出自己模块的周计划与交付物 |
| 相关经历 | 项目/作品链接、博客、竞赛经历（选填）；可附简历 |
| 附件 | 原型图、接口设计草稿等（选填） |

### 6.3 评审维度示例（管理用户评分参考）

| 维度 | 分值 | 说明 |
| --- | --- | --- |
| 技术基础 | 30 | 与所选模块技能要求的匹配度 |
| 方案可行性 | 30 | 对模块的理解与实施计划是否可行、边界是否清晰 |
| 相关经历 | 20 | 项目/作品/竞赛等佐证 |
| 表达与态度 | 20 | 陈述清晰、计划具体、可落地 |

- **通过线：60 分**；通过后按所选模块分配，未通过不释放评语外的信息（评语公开按系统配置）。
- 评审操作：通过 / 待定 / 拒绝（对应 OA 的 `APPROVED` / `ON_HOLD` / `REJECTED`）。

## 11. 与 OA 系统的关系说明
